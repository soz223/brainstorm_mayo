# RadOnc-GPT：用「只输入图像」查相似案例

## 1. 现在的系统是什么

- 现有功能：输入**文本** → 查到相似的东西。
- 实现原理（推测）：**向量数据库（vector database）**。
  - 系统先把每条数据变成一串数字（向量 / embedding）。
  - 查询时把你的文本也变成向量，然后找「向量最接近」的那几条。
- 数据库里同时存了**文本**和**图像**。

老师的新需求：**只给一张图像，就能查到相似的案例。**

一句话结论：**完全能做到。** 这是一个成熟的技术，叫「以图搜图」（content-based image retrieval / CBIR）。下面是三种做法，从最省事到最好。

---

## 2. 三种做法

### 做法 A：图像 → 先转成文字 → 走现有的文本查询（最省事）

- 用一个「看图说话」的模型（vision-language model）给图像生成一段文字描述。
- 把这段描述丢进**现在已有的文本查询**里。
- 优点：几乎不用改系统，最快能出原型。
- 缺点：图像信息会丢失一部分（文字描述说不清的细节就没了），效果取决于描述质量。

### 做法 B：图像 → 转成图像向量 → 单独建一个图像索引（经典以图搜图）

- 用一个**图像编码器（image encoder）**把图像变成向量。
- 把数据库里所有图像也都编码，单独建一个「图像向量索引」。
- 查询时：查询图像 → 向量 → 找最接近的图像。
- 优点：是真正的「图像相似」，细节保留好。
- 缺点：要新建一个索引；而且这样只能搜到「图像」，搜不到纯文本的案例。

### 做法 C：文本和图像放进**同一个**向量空间（推荐）

- 用一种「图文共享空间」的模型（CLIP 类模型）。
- 它的特点：**文字和图像被编码到同一个空间里** —— 一张肺部 CT 的向量，会和「肺癌」这段文字的向量靠得很近。
- 这样做之后：
  - 一张查询图像 → 一个向量 → 在**同一个索引**里，既能找到相似图像，**也能找到相关的文字案例**。
  - 现有的文本查询和新的图像查询，**共用一套索引**，系统结构最干净。
- 优点：图像查文本、文本查图像、图像查图像，全都通。
- 缺点：需要把数据库里的内容用这个新模型重新编码一遍（re-embedding）。

**建议：目标用做法 C；如果想先快速给老师看个 demo，可以先用做法 A。**

---

## 3. 医学场景要注意的点（radonc = 放射肿瘤学）

1. **不要用通用 CLIP。** 通用模型在自然图片上训练，看医学影像（CT/MRI/勾画/剂量分布）效果差。
   要用医学专用的图文模型，例如：
   - **BiomedCLIP**（生物医学图文，覆盖面广）
   - **PubMedCLIP** / **MedCLIP**（医学影像 + 文本）
   - 也可以用专门的医学影像基础模型做图像编码器。
2. **图像类型要先搞清楚。** RadOnc 里的「图像」可能是：CT、MRI、剂量分布图、器官勾画、病理切片……
   不同类型可能需要不同的编码器，或者分类型建索引。
3. **3D 影像问题。** CT/MRI 是三维的，但大多数现成模型只吃二维图。
   要么用 3D 编码器，要么按切片（slice）处理再聚合。
4. **隐私 / PHI。** 医学图像可能带病人信息，编码和存储都要符合合规要求；尽量本地部署，别传到外部 API。

---

## 4. 落地步骤（建议顺序）

1. **摸清数据**：数据库里到底有哪些图像类型、各多少张。
2. **选编码器**：先定一个医学图文模型（如 BiomedCLIP）。
3. **快速原型**：先做「做法 A」，给老师看一个能跑的 demo。
4. **重新编码**：用选定模型把数据库里的图像（和文本）重新编码，建索引（做法 C）。
5. **改查询入口**：在界面上加「上传图像」的入口。
6. **评估效果**：找一批已知答案的案例，看 Top-5 / Top-10 命中率，对比几个模型。

---

## 5. 给老师的一句话总结

> 能做到。原理和现在的文本查询一样，只是把「文本变向量」换成「图像变向量」。
> 最好的方案是用医学专用的「图文共享空间」模型（如 BiomedCLIP），
> 让图像和文本进入同一个向量空间——这样上传一张图，就能同时查到相似图像和相关文字案例，
> 而且和现有的文本查询共用一套索引。
